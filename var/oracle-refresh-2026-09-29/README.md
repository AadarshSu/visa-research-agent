# Selection oracle refresh, 2026-09-29 (DECISIONS entry 239)

Re-curates `oracle/selection_oracle.yaml` against the stores rebuilt on 2026-09-25. Run from the
repository root; nothing here touches the network or a model.

1. `candidates.py > review.txt` — per corridor and role, the top 8 by link, stored-text keywords and
   embedding similarity (the vectors in `../embed-replay-2026-09-28/vectors.sqlite`), plus every page
   any recorded replay picked; kept only where the stored text holds a passage of the role's kind,
   and not re-read where `same_pages` already credits it.
2. `regroup.py` — the same, one file per destination (`r_<destination>.txt`), each page once per
   role with the travellers it is a candidate for.
3. Read by hand; verdicts in `decisions.yaml`, each with the passage that decided it. `look.py` prints
   a stored page around a pattern, for checking what a passage only hinted.
4. `apply.py` — inserts the verdicts into the oracle line by line, so no existing line changes, and
   validates with `load_oracle`.

`review.txt` and `r_*.txt` are regenerated by steps 1 and 2 and are not committed.
